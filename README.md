## Что это

PoC бота, который продаёт eSIM для поездок. Я собрал его, чтобы проверить, как выглядит покупка eSIM внутри Telegram: не «магазин с корзиной», а короткий сценарий — выбрал регион, посмотрел тариф, сравнил с другим, оформил.

Данные и оплата — демонстрационные. Реального eSIM-провайдера, платёжного шлюза и выдачи QR здесь нет.

---

## Что умеет

- Каталог из **4 регионов**: Европа, США, Азия, Мир.
- **11 тарифов** с ценой, сроком, объёмом данных и покрытием.
- Карточка тарифа с постраничной навигацией «предыдущий / следующий».
- Сравнение двух тарифов бок о бок.
- Оформление заказа и экран «покупка успешна».
- История заказов с mock-данными.
- Раздел «Что такое eSIM» и инструкция по активации.
- Возврат в меню с любого экрана.

## Запуск

Нужен [Bun](https://bun.com) и токен от [@BotFather](https://t.me/BotFather).

```bash
bun install
cp .env.example .env
```

В `.env`:

```env
BOT_TOKEN=123456:AA...
```

```bash
bun run start
```

Если токен не задан, бот напишет ошибку и завершится — без «тихого» запуска с пустым токеном.

## Структура

```text
src/
├── infra/
│   ├── conversation-state.ts   # состояние диалога в памяти
│   ├── message-builder.ts      # сборка MarkdownV2-сообщений
│   └── telegram-bot.ts         # polling и маршрутизация callback'ов
└── views/
    └── telegram-views.ts       # экраны, клавиатуры, mock-данные
```

Экраны вынесены в `views`, инфраструктура — в `infra`. Это позволяет менять тексты и кнопки, не трогая цикл обработки обновлений.

---

## Как это работает

- Long polling через `getUpdates`.
- Все переходы — по `callback_data`; текст пользователь вводит только в сценариях, где это нужно.
- `MessageBuilder` экранирует MarkdownV2, чтобы цены, скобки и точки не ломали разметку.
- Состояние (`step`, выбранный регион, индекс тарифа, сравнение) хранится в `Map` по `chatId`.
- Тарифы и заказы — константы в `telegram-views.ts`. Заменить на API можно, не меняя сценарий.

---

## Ограничения

- Нет реальной оплаты: кнопка «Купить» показывает демо-экран.
- Нет выдачи QR-кода и интеграции с eSIM-провайдером.
- Нет базы данных: заказы и состояние живут в памяти.
- Нет авторизации, ролей и админки.
- Цены и покрытие — примеры, не оферта.
